# kms.jiup9.com 远端 OpenBao 测试方案

状态：待执行方案。2026-09-29 已核对本地项目代码和官方接口文档；本轮没有向目标服务发请求，没有验证 Token 有效性，也没有创建、读取或删除远端业务数据。文档不包含用户提供的凭据。

## 目标与结论

建议按“连接与健康 → 身份及明确路径权限 → SDK 只读冒烟 → 获准的隔离资源读写 → 回收与证据”执行。默认使用 `https://kms.jiup9.com:443` 作为待确认地址，不尝试 HTTP 降级、其他端口或其他主机。

本方案验证现有服务与 SDK 的接入行为。项目当前正式集成工具只接受自行创建、版本和摘要固定的临时实例，明确拒绝外部地址与凭据，不能直接把这个域名和 Token 填入 `BAO_TEST_ADDRESS` / `BAO_TEST_TOKEN` 后运行 integration-test。因此需要独立的远端冒烟入口；不得删除原拒绝条件来接入现有服务。

即使本方案全部通过，也不能自动认定 AC-065/066/070 或发布门禁通过。远端功能结果、独立 fixture 集成、固定扫描、跨平台验证分开报告。

## 执行前需要确定的最小输入

| 输入 | 已知与待确认内容 | 缺失时的影响 |
|---|---|---|
| 服务用途 | 域名已提供；需确认是独立测试、共享非生产，还是生产服务 | 不执行远端写入。若为生产，只制定获准的指定路径诊断范围，不自动套用非生产测试 |
| URL、TLS、namespace | 拟用 HTTPS 443；确认是否有 API 路径前缀、私有 CA、mTLS；namespace 必须明确为 root 或具体命名空间 | 不猜测 namespace，不发送凭据到未经确认的地址，不关闭证书验证 |
| 测试用身份 | 已提供一个 Token，但尚未查明 TTL、使用次数、权限和用途 | 不从 Token 字符串推断权限。建议执行前轮换已在聊天中出现的凭据，使用短期、限测试范围身份；无需再次粘贴明文 |
| 只读资源 | 提供一个非敏感、已知存在的 KV v2 mount、测试 path、准确 version | 没有该资源，只能证明连接/身份查询结果，不能证明 SDK 业务读取就绪 |
| 隔离写入范围 | 确认已有测试 mount、允许的独占前缀、允许创建/更新/软删除/恢复/最终回收的具体操作 | 只执行获准只读范围；不默认创建 namespace、mount、policy 或 Token |
| 可选 PKI / Transit | PKI 专用测试角色及允许的域名/TTL/信任根；Transit 专用测试 key 和允许操作 | 缺项明确 BLOCKED/NOT_RUN，不临时使用业务 CA、角色或业务密钥 |
| 正式集成条件 | 精确服务器版本和可信镜像 digest 或本地 binary SHA256 | 从健康接口读到 version 只属于 observed 信息，不能证明运行镜像摘要，也不能解除原 fixture 门禁 |

只读冒烟所需的核心补充信息是：环境性质、namespace、指定 KV v2 测试资源。需要 KV 写入测试时，再明确独占路径与回收权限；PKI/Transit 可以独立选择，缺少配置不阻止其他已获准检查。

## 分阶段验收矩阵

以下均为计划用例，目前均 NOT_RUN；表内“通过条件”不是实际测试结果。

| 阶段 | 操作与限制 | 通过条件 | 对原任务的意义 |
|---|---|---|---|
| 连接与 TLS | 解析指定域名，连接确认的 HTTPS 地址，验证证书链、主机名及有效期；不携带 Token，不跟随跨主机重定向 | TLS 校验成功，得到目标 API 响应；证书或重定向异常立即停止 | OB-003 的实际部署配置补充观察 |
| 集群健康 | SDK `ClusterHealth` 请求 `/v1/sys/health`，不带 Token/namespace；记录有限字段 | 正确解析 initialized、sealed、standby、version；按实际节点状态判断是否可继续 | OB-016 接入前置观察；不能证明凭据有效 |
| 身份与权限 | 在准确 namespace 内请求 `GET /v1/auth/token/lookup-self`；仅查询将使用的路径能力，不枚举全局资源 | 凭据可用、剩余时间/次数满足预算；具备选定测试动作的权限 | OB-016 身份/权限补充观察；自查接口被禁时不可反推 Token 必然失效 |
| SDK 只读冒烟 | 使用 `auth.NewStaticToken`、明确的 namespace/TLS 配置创建客户端，Start 后对指定非敏感版本运行 ReadVersion、CheckReady | 读回预先约定的测试标记；CheckReady 为 true；正常 Close；不输出读取内容 | OB-016 的实际 SDK 调用证据；New/Start 或健康成功本身不能替代业务读成功 |
| KV v2 隔离读写 | 仅在获准的独占 run_id 路径：CAS=0 创建、读取指定版本、CAS 更新、旧 CAS 冲突；许可时再软删/恢复自有版本 | 内容与版本一致；冲突没有覆盖已成功写入的数据；软删/恢复符合现有 SDK 契约 | 补充真实 KV 行为；不重放不确定写入，不碰已有业务 key |
| 权限负例 | 使用事先提供的受限测试身份与已约定的不可访问测试路径；不探测业务目录 | 返回既有契约对应的权限/隐藏响应；记录 HTTP 分类及 SDK 错误码 | 高权限单一 Token 不能证明最小权限边界；没有受限身份则该项 NOT_RUN，不自行签发新 Token |
| Transit，可选 | 只用预先确认存在的专用测试 key；测试字节 encrypt/decrypt，或按 key 类型 sign/verify；篡改签名负例 | 解密等于本地测试输入，正确签名通过、篡改失败；不会创建、轮换、导出或删除 key | 缺适用 key/权限则仅阻塞该项；先确认 key 已存在，避免隐式创建 |
| PKI，可选 | 优先本地生成临时私钥与 CSR，调用专用测试角色 SignCSR；若要测 Issue，另确认私钥返回及保管；限定测试域名、TTL | 证书链、SAN、用途、有效期符合明确策略；私钥只留必要的进程内存并释放 | 不创建/替换 CA，不用业务域名。签发与吊销会留下持久记录；只在获准测试 CA 范围内进行 |
| 回收与再次确认 | 根据本轮资源清单精确回收；只处理本次创建资源 | 能证明自有数据已删除或按约定到期；未回收项及原因完整列出 | 回收失败不得报告整轮完成；不得清空整个 mount 或 namespace |

健康接口的默认 200、429、501、503 分别表示活动可用、standby、未初始化、sealed。429 不能直接当成 Token 错误，也不通过强制改健康状态码掩盖真实状态；sealed/未初始化时只记录并停止业务检查，不执行 unseal/init。[OpenBao 健康接口](https://openbao.org/docs/api/system/health/)

权限预检使用 `POST /v1/sys/capabilities-self`，body 仅列出具体获准路径；这是权限查询，不修改 ACL。Token 自查响应可能含凭据标识，必须在内存中解析，只输出必要的 TTL/renewable 等允许字段，禁止保存完整响应。[权限自查接口](https://openbao.org/docs/api/system/capabilities-self/)、[Token 自查接口](https://openbao.org/docs/api/auth/token/)

所有认证请求仍可能产生服务端审计记录，受限次数 Token 也可能消耗使用次数；“只读”不意味着服务端完全没有副作用。404 不能单独证明路径不存在或权限隔离正确，须结合预先约定的负例与 SDK 隐藏语义判断。

## 隔离、预算与清理

1. 使用不可复用 run_id；在已获准测试 mount 中使用 `sdk-validation/<run_id>/...`，具体前缀由维护者确认。创建前确认无已有数据，以 CAS=0 防止覆盖；不能仅凭路径前缀就认定任何对象都属于本轮。
2. 建议只读阶段串行、最多 10 个 API 请求、总预算 90 秒；隔离功能阶段最多 60 个请求、总预算 10 分钟、并发最多 2。连接/TLS 各约 3 秒、普通请求约 5 秒，PKI 可使用现有 30 秒预算。达到预算即停止相关阶段，不自动扩大负载。这是测试限额，不是生产 SLA。
3. 测试配置令外层读重试次数为 1，便于观察一次请求的真实结果；保持 SDK 现有不确定写入不得重放的规则。写入超时或响应丢失时记 UNKNOWN，只允许有预算的独立读取来核对已知自有路径；不得因希望通过测试而补发同一写入。
4. 远端服务不做 fuzz、压测、强制断网/截断响应、封印、主从切换、全局配置或密钥轮换。取消、排队、响应丢失、畸形响应等破坏性故障注入继续在本地可控测试/独立 fixture 中验证。
5. KV 软删除仍保留底层数据，不能称为完全回收。最终删除 metadata 或 destroy 是不可逆操作，须在确认允许回收自有测试资源后执行，并逐项核对确切 mount/path/version 与创建记录；未获准则保留明确的待回收条目。[KV v2 删除与版本行为](https://openbao.org/docs/secrets/kv/kv-v2/)
6. PKI 签发不能用“删除本地证书”撤销；若选择该阶段，预先约定测试 CA、证书 TTL、是否允许吊销以及服务端记录保留方式。Transit 默认使用预置专用 key，完成后只清理本地测试材料，不改 key 配置。
7. 路径归属不明、观察到既有数据、权限超出预期、证书失败、持续 5xx/限流、清理不完整或凭据疑似进入输出时，停止受影响远端动作并保留脱敏摘要。不自动提权或操作服务来恢复。

## 入口与凭据传递设计

本轮只编写方案，以下是待实现的入口设计，不是已经存在或已经执行的命令：

- 建议增加独立 `scripts/remote-test.py` 和带显式 remote 标记的测试入口，默认只读；隔离写入模式须具备上述明确资源配置。复用当前 `command_runner`、`RunRecord` 和正式 SDK 工厂，不改变公开 API。
- 专用输入建议为 `BAO_REMOTE_ADDRESS`、`BAO_REMOTE_TOKEN`、明确的 namespace mode/path、KV mount/path/version，以及可选 PKI/Transit 参数。不要复用原独立 fixture 的 `BAO_TEST_*` 变量。启动前校验输入，不从环境中任意继承代理或跳过 TLS 的设置。
- Token 由执行进程的秘密注入机制传入，仅在需要时读取；不通过 CLI 参数、URL、脚本常量、配置文件、测试快照或报告传递。编译、版本探测及无关子进程不需要 Token；可先无凭据构建，再向测试进程定向注入。结束后清除本次设置的进程变量，不擅自撤销用户 Token。
- 不使用 `curl -v`、环境变量全集、HTTP dump、原始 lookup-self 响应或完整错误对象落日志。测试断言只输出用例名、有限状态、SDK 错误码和必要的脱敏信息；不能先保存秘密日志再依赖事后脱敏。
- Observer 回调保持快速，标签限定为测试阶段、操作和错误码等有限集合；不把 Token、path、证书或请求体作为标签。回调本身不额外请求服务器。
- 用现有 `record.py` 的 `COMMAND_RECEIPT` 收集真实子进程收据与脱敏输出，另附明确标为远端接入补充结果的报告。不得把该报告标为 `REAL_OPENBAO`，不得为它放宽 `acceptance-rules.json`。

新脚本/测试会改变 source_identity。若后续实现该入口，应先完成局部回归并冻结新指纹，再运行远端检查和受影响的既有门禁；不能把本轮已有 Go/Python 通过报告仅修改 hash 后继续使用。

## 证据与验收口径

执行后保存到新的 `.artifacts/runs/<run_id>/remote/`：目标地址与环境说明、实际 SDK 源码标识、观察到的服务版本、Go/Python/平台版本、真实 argv/cwd、起止时间、自然退出码、请求目标类别与计数、逐用例结果、日志摘要和资源回收清单。不记录 Token、accessor、请求正文、KV 读值、私钥或完整环境变量。

状态使用 PASS / FAIL / BLOCKED / NOT_RUN。PASS 必须对应真实目标执行；零测试、错误过滤、skip、无权限或只看到 HTTP 200 都不算业务用例通过。保留首次失败、超时、UNKNOWN 与后续核对记录。

本方案主要关联 OB-003 的部署配置观察、OB-016 的接入验证和 OB-018 的证据整理。只有在原验收契约正式批准接受另一种集成模式后，才可能改变 AC-065 等门禁归属；本次不提出或实施这种放宽。执行结果可作为原台账的补充说明，不塞入只接受正式证据类别的 `evidence` 字段，不建立第二套任务台账。

建议本轮首批执行边界：确认环境、namespace 与一个专用 KV v2 只读资源后，完成 TLS、健康、凭据/路径能力和 SDK 只读冒烟；已确认独占测试前缀及回收权限时，再连续完成 KV 读写。PKI/Transit 依据现成专用资源加入，不用缺少它们阻塞已获准的独立阶段。
