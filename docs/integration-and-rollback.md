# 业务接入与回滚（OB-019 未执行）

当前没有真实 saas-go/yacht 调用项目源码、测试环境或旧凭据样本。本文是接入操作说明，不是迁移成功记录，也没有修改已有业务仓库。

首先在业务启动层创建SDK并注入窄接口；保留上层授权和命名规则。按真实配置选择Namespace，不能把用户输入直接变成管理员身份下的路径。原始秘密不进入MySQL、MQTT、Webhook、Outbox或日志，只保存Ref和允许的非秘密元数据。

读迁移可以在明确权限范围的隔离测试环境比对旧读与SDK准确版本读；发证/写操作**不得双写影子流量**。将特定任务的唯一执行权切到一个适配器，使用 durable generation claim 防止进程重启导致重复发证。

回滚只切换适配器实现，继续保留先前SecretRef、operation_id、resource_generation、序列号和历史版本。不能回滚时删除新证书/秘密、重建所有版本，或将不匹配引用替换为latest。签发响应未知要进入人工核对/受控补发代次，不普通重试。

实际验收需要：现有调用点清单、隔离环境身份、旧新读取对比、一次真实写入的独占任务记录、故障恢复、回滚前后同一历史引用仍可解析；缺任一项，OB-019/AC-072仍未通过。

## 消费方实现责任（2026-10-04 交接准备）

以下为待真实业务项目落实和核验的接入要求，不是已完成的迁移。参考 `examples/credentialworkflow/workflow.go`，该示例的接口和模拟测试不提供生产数据库、持久日志或跨外部服务事务。

| 边界 | 消费方责任 |
| --- | --- |
| `Issuer.Issue` | 通过既有业务授权和专用 PKI 角色签发；一次持久领取对应一次调用。返回的敏感材料按所有权及时清理；超时/响应未知不能普通重试或再签一张。 |
| `Store.Find/Create` | 使用准确的 `Generation` 核对归属和内容，保存可回读的准确 `SecretRef`；Create 使用消费方认可的 CAS/唯一性控制。只有确知未存储才能返回 `ErrNotStored`，隐藏/权限错误不能当作不存在。保存结果未知时核对同一代次，不改为 latest，不重新 Issue。 |
| `Journal.Load/Claim/Save` | Claim 必须在持久层原子竞争并在 Issue 前持久化，不能用进程内 map、缓存或写前查询代替唯一约束。明确租户及资源作用域，持久记录 `operation_id`、`resource_generation`、path、Claimed/Unknown/Ready 和准确 Ref；Ready 仅在材料保存并完成核对后持久化。 |
| 业务编排与恢复 | 数据库事务不覆盖 OpenBao 副作用。已领取后进程中断、签发响应未知、材料保存或 Ready 记录失败时保留原代次，进入核对；不得因超时释放领取并盲目再次签发。轮转使用显式新代次，注册及发布需区分本轮凭据和历史引用。 |

示例先 Load/Find，再执行原子 Claim；已有领取但未核实保存材料时返回 `ErrUnknown`，不会在重启后再调用 Issue。Store 保存错误后仅 Find 核对，未再次签发。真实适配器必须验证同一代次、归属及内容一致性，不能以 HTTP 200、日志或“路径存在”代替持久化证据。

## AC-072 的非生产验收与解除条件

| 场景 | 实际接入通过条件（本轮 NOT_RUN） |
| --- | --- |
| 并发与原子领取 | 同一业务代次多进程竞争只有一个 Issuer 调用；失败竞争者核对既有记录，不双写发证。 |
| 发证后中断与重启 | 在领取后、Issue 后和 Store/Journal 提交边界注入中断；重启仍不再次签发，Unknown 可用可信持久事实核对。 |
| 保存结果未知 | Create/Ready 返回超时或失联时，按准确代次读取并核对归属、内容和 Ref；核对不充分保持未知，不吞错、不换 latest。 |
| 轮转与历史引用 | 新代次只替换本轮业务引用；旧版本、序列号、operation_id 和准确 Ref 继续可解析，不被覆盖。 |
| 回滚演练 | 关闭本轮写适配器后切回旧实现；回滚前后的同一历史引用和业务映射一致，不删除新材料、不重建所有证书。 |
| 精确数字字段 | 经消费方批准的 JSON 字符串 ID 在实际 HTTP、业务存储、事件及旧新适配器回滚链路中类型和值均保持一致。 |

解除阻塞最小输入：实际业务仓库的绝对路径/模块、分支与工作树基线、已授权的调用点和改动范围；消费方认可的代次/归属/持久化契约；隔离非生产环境、限权限身份注入方式、专用 PKI role/测试域名/KV mount 和独占资源前缀；无敏感原文的历史引用样本、故障注入与回收范围、业务回滚授权。不要在聊天或日志中粘贴 Token、私钥或原始凭据。

SDK V1 门禁为 AC-001～071；本轮未提供上述业务输入，OB-019 保持 BLOCKED/OUT_OF_SCOPE，AC-072 保持 NOT_RUN。SDK 本地测试或发布门禁通过均不能升级业务接入状态。

## 精确数字字段的消费者契约建议

对必须精确的业务 ID/大整数，建议消费方 DTO 和存储/事件协议使用 JSON 字符串，例如 `{"business_id":"9007199254740993"}`，Go 字段使用 `string`，避免经 `float64` 或 JavaScript Number 中转。正负、范围、前导零和校验规则由消费方明确批准，不在 SDK 内猜测或转换既有数值字段。

实际接入验收同时检查字段类型仍为字符串、完整值没有变化，覆盖写入/读回、跨服务传输、历史版本及回滚。`kv.Document` 本地数字往返不证明服务端端到端精度；固定 OpenBao 2.6.3 的既有精度观察见[兼容性边界](compatibility.md)。本轮未重新运行真实服务探针。
