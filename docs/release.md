# 发布检查

当前实现没有版本发布、远端仓库、push、release或部署。不要运行 git tag/push 来掩盖未通过门禁。

1. OB-001核验完整官方依赖与Go要求，合法生成并审查go.sum；确定正式module路径，更新本仓库导入及消费者require。
2. 由权利人确定源码授权/许可证，不由AI擅自代为选择。
3. 配置经过可信来源核验的服务端版本与镜像digest/二进制SHA256，运行正常、真实集成、独立消费者和固定扫描。
4. 全部AC001–071满足相应要求后由维护者根据证据更新台账；运行make release-check。台账标绿不是测试，报告必须与当前source hash和正确证据等级匹配。
5. 经明确授权才发布第一个v0.x版本。v1.0仅在兼容契约稳定后使用；破坏性变更需要独立主版本和模块路径管理。

发布门禁不要求把AC072伪造成已完成；真实业务接入单独报告。源代码ZIP是当前实施快照，不是服务器部署包，包含失败与未执行证据也是合理交付，但不能作为release artifact对外标稳定。

CI使用固定commit的checkout/setup-go，仅contents:read、关闭凭据持久化，无发布步骤。它尚未在远端运行。缺真实集成变量时该job失败，不通过条件跳过变绿。
