# OpenBao Go SDK 接口契约

**版本：1.0｜设计级 Go 签名，不是已经发布的 SDK。**

本文件固定名称、参数、返回值和失败语义。示例中的 module path 使用 `git.example.com/infra/openbao-sdk-go`，实施时统一替换为实际仓库域名。以下代码块按所属包展示，省略 import、私有状态与方法体；不是一份可以直接编译的完整源码。

## 1. 根包 bao

```go
func New(cfg Config, opts ...Option) (*Client, error)

func (c *Client) Start(lifecycleCtx context.Context) error
func (c *Client) Close(shutdownCtx context.Context) error
func (c *Client) State() diagnostics.ClientState

func (c *Client) KVv2(mount string) (*KVClient, error)
func (c *Client) PKI(mount string) (*PKIClient, error)
func (c *Client) Transit(mount string) (*TransitClient, error)

func (c *Client) ClusterHealth(ctx context.Context) (*diagnostics.Health, error)
func (c *Client) CheckReady(ctx context.Context, probe diagnostics.ReadProbe) (*diagnostics.Readiness, error)

func WithObserver(observer observe.Observer) Option
```

KVv2/PKI/Transit 只校验挂载并返回绑定门面，不联网。网络方法只在生命周期允许、凭据可用时发送。New 失败不留下 goroutine。所有返回 *Result 的网络方法只在 error=nil 时承诺完整结果；V1 不通过 result+error 混合传递未校验私钥，错误中只能附带经过校验的非秘密部分回执。

```go
type Config struct {
    Address      string
    ClusterAlias string
    Namespace    NamespaceConfig
    Auth         auth.Config
    TLS          TLSConfig
    Network      NetworkConfig
    Timeouts     TimeoutConfig
    Limits       LimitConfig
    ReadRetry    ReadRetryConfig
}

type NamespaceMode string
const (
    NamespaceRoot  NamespaceMode = "root"
    NamespaceNamed NamespaceMode = "named"
)
type NamespaceConfig struct {
    Mode NamespaceMode // 必填，空值错误。
    Path string        // named 必填；root 必须为空。
}

type TLSConfig struct {
    CAFile         string
    CAPEM          []byte
    ServerName     string
    ClientCertFile string
    ClientKeyFile  string
    ClientCertPEM  []byte
    ClientKeyPEM   sensitive.Bytes
    MinVersion     uint16
}

type NetworkConfig struct {
    ProxyURL           string // 默认不使用环境代理。
    MaxIdleConnections int
    MaxIdlePerHost      int
    IdleConnTimeout    time.Duration
}

type TimeoutConfig struct {
    Request      time.Duration // 默认 10 秒。
    PKIIssue     time.Duration // 默认 30 秒，覆盖 Issue/SignCSR。
    Login        time.Duration // 默认 10 秒。
    Renew        time.Duration // 默认 5 秒。
    Dial         time.Duration // 默认 5 秒。
    TLSHandshake time.Duration // 默认 5 秒。
}

type LimitConfig struct {
    MaxConcurrentRequests int   // 默认 32。
    MaxRequestBytes       int64 // 默认 1 MiB。
    MaxResponseBytes      int64 // 默认 2 MiB，解压后。
    MaxResponseHeaderBytes int64 // 默认 64 KiB。
}

type ReadRetryConfig struct {
    MaxAttempts int           // 默认 3；1 表示禁止外层重试。
    BaseDelay   time.Duration // 默认 100ms。
    MaxDelay    time.Duration // 默认 2s。
}
```

CAFile 与 CAPEM 互斥；证书密钥文件模式与内存模式互斥，并要求证书和私钥成对。没有 InsecureSkipVerify、任意 Header 注入、RawClient 或任意 HTTPClient 的公开选项。公开配置中所有秘密包装类型禁止普通 JSON 序列化；项目配置加载层读取文件或受控环境变量后转换。

零超时/零限制使用明确默认值，负值报错；MaxAttempts=1 允许禁用读取重试，不能用负值表达无限次数。所有 Config 的可变切片在 New 时复制。

## 2. auth 包

```go
type Mode string
const (
    ExternalToken Mode = "external_token"
    ManagedAppRole Mode = "managed_approle"
)

type Config struct {
    Mode          Mode
    TokenProvider TokenProvider  // ExternalToken 必填。
    AppRole       *AppRoleConfig // ManagedAppRole 必填，与 TokenProvider 互斥。

type TokenSnapshot struct {
    Token      sensitive.Bytes
    Generation string    // 本地非秘密标识，不记录 Token 内容。
    ValidUntil time.Time // 零值表示未知，不表示永久有效。
}

type TokenProvider interface {
    Snapshot(ctx context.Context) (TokenSnapshot, error)
}

type AppRoleConfig struct {
    Mount            string // 相对 auth/ 的挂载，如 approle。
    RoleID           sensitive.Bytes
    SecretIDProvider SecretIDProvider
}

type SecretIDUse string
const (
    ReusableSecretID SecretIDUse = "reusable"
    SingleUseSecretID SecretIDUse = "single_use"
)
type SecretIDSnapshot struct {
    SecretID   sensitive.Bytes
    Generation string
    Use        SecretIDUse
}
type SecretIDProvider interface {
    Current(ctx context.Context) (SecretIDSnapshot, error)
}

func NewStaticToken(token sensitive.Bytes) (TokenProvider, error)
func NewTokenFile(path string) (TokenProvider, error)
func NewSecretIDFile(path string, use SecretIDUse) (SecretIDProvider, error)
```

TokenProvider 和 SecretIDProvider 必须遵守 Context 取消、不输出秘密、不启动未声明的永久任务。StaticToken 无续期承诺。

单次使用 SecretID 的 generation 在请求发送前标记“已尝试”，同一进程不能再次发送同 generation；新 generation 由外部供应，不由 SDK 自造。重启后的 exactly-once 无法仅靠内存保证，部署方必须供应新凭据或容忍旧凭据被服务器拒绝；登录响应丢失必须可观测，不能把它算作没有消耗。

ValidateBundle 要求至少一个受信根和非空 RequiredEKUs；缺失时失败，不默认把 MQTT 客户端证书按服务端用途验证。ReadCertificate 可遇到包含多个 PEM 块的证书字段，必须正确提取叶证书并校验序列号，不能将拼接链当成单个 DER。

ReadIssuerChain 读取当前默认 issuer 的链；不得替代历史 IssueResult 中保存的链。V1 没有 caller 指定任意 issuer 覆盖接口。CertificateRecord 不是私钥保存记录，不因被删除或清理就推断未曾签发。

V1 profile 的 wire 参数：ECDSA 设置 hash_algorithm=sha2-256、marshaling_algorithm=asn1；RSA 设置 hash_algorithm=sha2-256、signature_algorithm=pss、salt_length=hash；Ed25519 不预散列，使用该类型规定的消息签名语义。SignDigest/VerifyDigest 对允许的 profile 设置 prehashed=true，并先校验摘要长度。所有签名包装的实际版本都必须匹配请求版本。[S14]

SPKIDER 是 SDK 的统一表示：根据官方返回的密钥类型解析，不假设每一种公钥的原始响应都是同一种 PEM 或 Base64。密钥元数据预检与签名之间不是事务，服务器是最终能力裁决者；预检失败不自动增加权限或改变算法。

## 9. HTTP 映射

全部 API 路径均由固定模板构造，前缀 `/v1` 只添加一次。表中 `{mount}` 为相应 secrets engine 挂载；auth mount 使用 `{authMount}`。SDK 不接受调用方输入完整 URL。[S06][S10][S12][S14][S16][S18]

| SDK 操作 | Method | 相对 /v1 的路径 | 关键约束 |
|---|---|---|---|
| AppRole 登录 | POST | /auth/{authMount}/login | role_id、secret_id；请求级凭据隔离 |
| 续期自身令牌 | POST | /auth/token/renew-self | 对目标快照续期，不混入新的 Token |
| Create | POST | /{mount}/data/{path} | options.cas=0 |
| CompareAndSwap | POST | /{mount}/data/{path} | options.cas=expectedVersion>0 |
| ReadVersion | GET | /{mount}/data/{path}?version=N | N>0 |
| ReadLatest | GET | /{mount}/data/{path} | 返回实际版本 |
| ReadMetadata | GET | /{mount}/metadata/{path} | 不授予无关 sys 权限 |
| List | LIST | /{mount}/metadata/{prefix} | 不自动递归；不静默换 GET |
| DeleteVersions | POST | /{mount}/delete/{path} | versions 非空 |
| UndeleteVersions | POST | /{mount}/undelete/{path} | versions 非空 |
| Issue | POST | /{mount}/issue/{role} | format=pem、private_key_format=pkcs8 |
| SignCSR | POST | /{mount}/sign/{role} | csr、ttl；不请求或返回调用方私钥 |
| ReadCertificate | GET | /{mount}/cert/{serial} | JSON 证书记录 |
| ReadIssuerChain | GET | /{mount}/ca_chain | PEM 链，使用 raw 有界解码 |
| Revoke | POST | /{mount}/revoke | serial_number |
| Sign / SignDigest | POST | /{mount}/sign/{name} | 明确版本/profile/prehashed |
| Verify / VerifyDigest | POST | /{mount}/verify/{name} | 包装签名版本先本地验证 |
| ReadPublicKey / ReadKeyMetadata | GET | /{mount}/keys/{name} | 从 keys[N] 选择，不能构造虚假版本端点 |
| Encrypt | POST | /{mount}/encrypt/{name} | 已有密钥，明确 key_version |
| Decrypt | POST | /{mount}/decrypt/{name} | ciphertext 与必要 context |
| Rewrap | POST | /{mount}/rewrap/{name} | 目标 key_version |
| HMAC | POST | /{mount}/hmac/{name}/sha2-256 | 明确 key_version |
| HMACVerify | POST | /{mount}/verify/{name}/sha2-256 | hmac、input |
| ClusterHealth | GET | /sys/health | 独立无 Token、无 Namespace 客户端 |

## 10. 业务调用顺序示例（流程契约）

```text
启动：
  读取项目自己的配置 -> bao.New -> Start(服务根Context)
  -> 构造业务窄接口 adapter -> 启动 HTTP/后台任务

证书保管：
  PKI(mount) -> Issue -> ValidateBundle
  -> kv.NewDocument(业务凭据封装)
  -> KVv2(mount).Create -> 保存返回 Ref
  -> ReadRef -> 校验 operation_id 与 generation

平台签名：
  获取业务批准的 KeyName + Version + Profile
  -> 对规范化消息字节 Sign
  -> 保存包装签名、版本与业务消息协议版本

停止：
  停止接收新业务 -> Close(有截止时间的关闭Context)
```

真实 Go examples 要在实现阶段与 SDK 一起编译、测试；本次不把这些设计调用当成已经可运行的软件。

## 11. 稳定错误码字符串

公开常量置于 baoerr 包，Code 对应固定 snake_case 字符串：

```text
CodeInvalidArgument       = invalid_argument
CodeAuthenticationFailed  = authentication_failed
CodePermissionDenied      = permission_denied
CodeNotFoundOrHidden      = not_found_or_hidden
CodeVersionUnavailable    = version_unavailable
CodeCASConflict           = cas_conflict
CodeCanceled              = canceled
CodeDeadlineExceeded      = deadline_exceeded
CodeUnavailable           = unavailable
CodeInvalidResponse       = invalid_response
CodeResponseTooLarge      = response_too_large
CodeRedirectBlocked       = redirect_blocked
CodeNotReady              = not_ready
CodeClosed                = closed
```

本地请求体超限归 invalid_argument，远端响应超限归 response_too_large。任意 Code 都不能代替 Effect：例如 deadline_exceeded + unknown 表示写结果未知，不代表可自动再写。
