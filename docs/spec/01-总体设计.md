# OpenBao Go SDK 总体设计方案

**方案版本：1.0｜编写日期：2026-09-28｜交付性质：设计与实施规格，不是已实现 SDK。**

## 1. 目标、依据与适用边界

建设独立仓库、独立 Go Module 的 `openbao-sdk-go`，供 SaaS、IoT、后台任务和命令行工具复用。以官方 `github.com/openbao/openbao/api/v2` 为通信基础；封装稳定接口、安全默认值、认证生命周期、明确的失败语义与测试契约，不重新实现 OpenBao，也不开发 OpenBao 服务端插件。[S01]

已提供的 `saas-go` 工程说明记录：后端服务分别拥有 go.mod，共享库仅承载无业务语义的基础能力。因此 SDK 不反向依赖 saas-go，不依赖 Gin、Fiber、Gorm、Redis、EMQX 或项目领域对象。服务在 bootstrap 中初始化 SDK，在自身 adapter/service 层调用。[P01]

本方案的技术行为参照官方文档核实；超时、并发、接口命名、阶段范围等是本方案的设计决定，不是 OpenBao 官方默认值。既有项目结构说明是文件快照，不是本次对真实仓库的扫描结论。没有使用商品或交易 SQL 推导 SDK 表结构；SDK 自身没有业务数据库。

### 1.1 明确的交付目标

调用方能够安全完成：外部令牌或 AppRole 接入；KV v2 版本化秘密存储；PKI 签发、CSR 签名、查询与吊销；Transit 指定版本签名、验签、公钥读取及常用加密操作。至少用两个互不依赖的调用项目验证复用。

必须保证：身份与 Namespace 不串用；私钥不会被隐式忽略或默认记录；写操作不盲目重放；准确版本不回退到 latest；网络结果未知不会伪装成明确失败；测试报告区分 mock、真实临时 OpenBao 与生产验证。

### 1.2 第一版范围

| 领域 | V1 必须交付 | 不包含在 V1 运行时接口 |
|---|---|---|
| Core | 配置校验、TLS、Context、连接复用、限并发、请求执行、错误脱敏 | 通用任意 URL 代理、全局单例、运行中身份切换 |
| Auth | 外部 Token Provider、Token 文件、SDK 管理的 AppRole 登录/续期/重登 | Kubernetes/JWT/OIDC、自动生成 SecretID、自动提权 |
| KV v2 | 仅创建、准确版本/最新版本读取、CAS 更新、列表、元数据、指定版本软删除/恢复 | 永久销毁、删除全部元数据、自动覆盖、自动 rw patch 回退 |
| PKI | Issue、SignCSR、ReadCertificate、ReadIssuerChain、Revoke；本地材料校验 | 创建根 CA、修改 PKI Role、任意 issuer 覆盖、自动发证并落库 |
| Transit | 签名/验签、公钥与元数据、加密/解密/重包裹、HMAC/验证 | 创建/删除/轮换密钥、私钥导出、明文备份 |
| Diagnostics | 本地生命周期状态、独立集群健康探针、可选业务读就绪探针 | 初始化、解封、Root Token、后台全库扫描 |
| 工程 | 单元、契约、临时真实服务测试，示例，文档，版本发布规范 | 宣称全 OpenBao API 或全版本兼容 |

管理端能力在第 19 节作为独立扩展规格说明，不因它们未进入运行时 V1 就给业务服务管理权限。

## 2. 方案选择

| 方案 | 优点 | 代价 | 本方案决定 |
|---|---|---|---|
| 各项目直接调用官方客户端 | 接入短、抽象少 | 认证、重试、脱敏规则容易分叉 | 用作底层，不作为跨项目治理方式 |
| 官方客户端之上的薄 SDK | 统一安全契约、无新增服务、可版本发布 | 需要维护有限的公开接口与测试 | 采用 |
| 自建远程密钥网关 | 可统一多语言权限与流量控制 | 增加服务、网络跳数、部署和高可用责任 | 暂不建设；将来按独立项目评估 |

“薄”并不等于没有可靠性治理。SDK 不承载游艇/租户/订单业务，但必须承载请求是否可以重试、凭据如何轮换、敏感结果如何传递等客户端语义。

## 3. 架构与依赖方向

```text
Go 业务服务 / 后台任务 / CLI
          |
项目自己的 adapter / usecase
          |
公开包 bao：Client / KVClient / PKIClient / TransitClient
          |                         |
内部请求执行器                  Auth Manager
          |                         |
官方 api/v2 客户端              Token Provider / AppRole
          |
复用的受控 HTTP Transport + TLS
          |
指定 OpenBao 集群与 Namespace
```

公开客户端类型统一放在根包 `bao`；`kv`、`pki`、`transit`、`auth`、`baoerr`、`sensitive`、`diagnostics`、`observe` 为叶子类型/工具包。这样根包可以引用各模块类型，模块类型包不反向引用根包，公开构造函数也不会暴露 internal 类型。

运行时 SDK 只拥有：配置快照、HTTP 连接资源、认证状态、当前凭据快照、必要的同步对象与观察钩子。它不拥有业务锁、MySQL 事务、重试任务表、注册状态、MQTT 连接或 webhook 消费者。

## 4. 版本与兼容性策略

已核实官方客户端存在 `api/v2@v2.7.0` 及相应源码；本文用它说明 `NewConfig`、禁用环境变量、重试和重定向行为，不把它称为最新版本，也不推断你实际部署的服务端就是 2.7。[S02][S03]

实施任务 OB-001 必须固定以下四项：SDK module path；Go 工具链及 go 指令；官方 api/v2 的精确 tag 与校验；测试服务端镜像的版本和 digest。候选官方依赖是 `v2.7.0`，选择其他版本须重新核对本方案涉及的 API 行为。应先读取该依赖的 go.mod 最低要求，再与团队批准的工具链取交集；不根据本文替现有服务擅自升级 Go。

`saas-go` 文件中记录的 Go 1.26.3 只是该文件快照。[P01] 兼容矩阵必须分开记录“拟支持”“已编译”“真实集成通过”，没有测试过的服务端不得标记为兼容。CI 不使用浮动 latest 镜像。升级客户端与升级 OpenBao 服务端是两个独立变更。

## 5. 配置与安全默认值

### 5.1 配置规则

`New` 只接收显式 Config，不自动读取 BAO_*、VAULT_*、HTTP_PROXY 等环境变量；调用项目的配置层负责读取环境变量并构造 Config。使用官方 `NewConfig()` 而非隐式环境加载的 `DefaultConfig()`，并显式设定底层重试和重定向。[S03]

Address 仅允许 scheme + host + port，不能包含用户密码、query、fragment 或业务路径；V1 不支持反向代理子路径前缀。集群别名仅供本地配置解析，不能从外部 SecretRef 中取一个 URL 直接请求。

Namespace 必须显式选择 `root` 或 `named` 模式；零值无效。named 模式必须给出规范化路径。禁止用户输入任意 Namespace 或挂载路径后直接透传。`xyouting-test` 作为接入配置候选值保留，实际是否 Namespace 要在部署接入记录中核实；核实前不得静默改为根空间。[S04]

### 5.2 设计默认值

| 配置 | V1 默认值/约束 | 说明 |
|---|---|---|
| scheme | HTTPS | 普通接口不提供关闭证书验证开关 |
| 最低 TLS | 1.2 | 可由部署配置提高为 1.3 |
| 普通操作总预算 | 10 秒 | 包括排队、认证等待、重试等待、响应读取 |
| PKI Issue / SignCSR | 30 秒 | 有更早调用方 deadline 时服从更早值 |
| AppRole 初次登录 | 10 秒 | 不依赖调用方设置无限等待 |
| 续期单次预算 | 5 秒 | 与普通业务请求隔离 |
| Dial / TLS 握手 | 各 5 秒 | 纳入整体预算 |
| HTTP Client.Timeout | 0 | 不是无限请求；所有请求强制有 SDK Context 总预算 |
| 允许重试的读取 | 最多 3 次尝试 | 包含第一次；不是再重试 3 次 |
| 非读取操作 | 1 次尝试 | 认证重登也不自动重放原写请求 |
| 退避 | 基数 100ms，上限 2s，full jitter | 总预算耗尽立即结束 |
| 每客户端业务并发 | 32 | 等待队列不创建无限 goroutine，等待可取消 |
| 认证并发 | 独立，单次登录/续期合并 | 避免业务流量耗尽所有槽位 |
| HTTP 最大空闲连接 | 64；每主机 32 | 空闲连接超时 90 秒 |
| 请求 JSON 上限 | 1 MiB | 设计默认，可显式调整 |
| 响应体上限 | 2 MiB | 解压后计数，认证与错误响应也受限 |
| 响应头上限 | 64 KiB | 设计限制 |
| Token 文件上限 | 64 KiB | 空文件、截断或控制字符返回错误 |
| KV JSON 最大嵌套 | 64 | 拒绝重复对象键与超深输入 |
| 私钥/秘密缓存 | 关闭 | 禁止本地磁盘、Redis 或普通进程全局缓存 |
| 自动重定向 | 关闭 | 包括官方客户端与 net/http 两层 |
| 自动代理 | 关闭 | 需要代理时显式配置可信代理 |

以上均为 SDK 设计值，不是性能实测承诺。最终合理性通过真实负载测试确认。

CA 文件与内存 PEM、客户端证书文件与内存材料采用互斥配置：同一用途同时配置两种来源直接报错，不依靠隐式优先级。自定义 CA 是受控信任集合；OpenBao 服务端 TLS CA 与 PKI 签发体系 CA 必须分开。

本地临时集成环境可以通过测试专用构造器允许 loopback HTTP；它不进入常规业务示例，且不得作为生产降级路径。测试 OpenBao 在容器里时，将端口绑定到宿主 loopback，由宿主测试进程调用。

## 6. 客户端生命周期

公开协议为 `New(cfg)`、`Start(lifecycleCtx)`、`State()`、`Close(shutdownCtx)`。所有模式都显式 Start。

```text
CREATED -> STARTING -> READY
                 \-> CREATED（初始化失败，可显式再次 Start）
READY <-> DEGRADED（重登/续期暂时不可用，但旧令牌仍有效）
READY/DEGRADED -> AUTH_UNAVAILABLE（没有可用凭据）
AUTH_UNAVAILABLE -> READY（受控重登成功）
任意已创建状态 -> CLOSING -> CLOSED
```

New 不联网、不发证、不启动 goroutine。Start 成功后只启动所选认证模式需要的任务；并发 Start 合并，READY 后再次 Start 返回成功；CLOSED 后禁止重启。外部模式的 READY 表示提供器能给出本地可用凭据，不代表每一条服务器 ACL 都已验证。

Start 必须使用服务根生命周期 Context，不能传入“启动后 defer cancel”的短期 Context。首次登录另外受 10 秒预算限制。正常关闭应先停止服务接收新业务，再调用 Close 排空已进入请求；超过 shutdownCtx 时取消剩余请求。被取消的写操作仍可能是结果未知。

SDK 只关闭自己创建的 Transport 和 goroutine；Close 不撤销外部令牌，不默认撤销 SDK 登录令牌，不删除 KV 或吊销证书。V1 不接收任意外部 http.Client，避免资源所有权和重试语义不可控；仅提供受限 Observer 和显式网络配置。

## 7. 认证设计

### 7.1 外部令牌模式

外部 TokenProvider 在每次请求真正发送前提供令牌快照；不能在等待并发槽位前读取令牌后长时间排队。提供器返回令牌、可选本地有效期、非秘密 generation。SDK 不替该模式续期或重新登录。StaticTokenProvider 明确表示外部负责有效性，不自动称令牌永不过期。

TokenFileProvider 每次打开指定文件读取完整内容，trim 首尾空白，校验长度和控制字符，不在新文件不可读时静默使用历史令牌。文件由 Agent/部署系统原子替换；读取与权限检查尽量基于同一已打开文件描述符。Token/SecretID 文件提供器的 Generation 使用进程内随机密钥对内容计算 HMAC-SHA256，而不是 mtime；重写相同秘密不能被误当作新的单次凭据。该标识不作持久身份，重启后由外部重新供应一次性凭据。允许受信部署系统的符号链接挂载，但必须记录挂载目录的信任边界。SDK 的文件读取不是对恶意本机管理员的安全隔离。

OpenBao Agent 可负责认证、续期和再次登录；使用它时 SDK 不运行第二套生命周期管理。[S05] V1 只支持读取未被 response wrapping 的 Token sink；包装 Token 的获取/解包属于独立后续能力，不猜测文件内容类型。

### 7.2 SDK 管理 AppRole 模式

配置 auth mount、RoleID、SecretIDProvider。SecretIDProvider 在每次新的登录动作时读取当前凭据，支持受保护文件或宿主自定义实现。SDK 不持有生成 SecretID 的管理权限。[S06]

认证流程：取得 SecretID -> 单次调用 `auth/{mount}/login` -> 校验 auth.client_token、lease_duration、renewable -> 发布不可变令牌快照 -> 到期前续期；续期失败先区分网络短暂失败、不可续期/最大 TTL、明确认证失败。

续期计划以**最近一次服务器返回的 lease_duration**和本地单调时钟计算，并保守扣除本次请求已消耗的时间，不能收到延迟响应后重新计满全部 TTL。建议在剩余生命周期充足时续期，并带抖动；不假设原 TTL 永远不变。不续期的令牌在到期前重新登录。TTL 缺失或非正数不能被误判成永久有效；SDK 管理模式应拒绝不满足生命周期契约的响应。

同一客户端同时只允许一个登录/续期协调动作。短暂网络错误可在当前凭据有效窗口内退避；凭据耗尽、文件缺失或明确认证失败进入 AUTH_UNAVAILABLE 并抑制高频重登。SecretID 有有效期与使用次数，单次登录响应丢失可能已消耗一次使用次数，不能盲目重放同一份一次性 SecretID。[S06]

SDK 管理模式 v1 不支持无限使用次数以外的业务 Token 配额自动预算；接入策略应将 `token_num_uses=0`，以 TTL 和 ACL 管理，而不是让后台续期/探针不可预测地消耗有限使用次数。此处 0 代表使用次数不受限，不代表有效期无限。

### 7.3 403 不是“刷新一下就行”

403 可能是 ACL 不足，也可能是认证详情无效，不能一律触发重登。[S08] 默认返回错误。只有生命周期证据表明本地凭据过期或续期接口确认不可用，才启动认证恢复。恢复是后续调用的准备动作，绝不自动重放原始发证/写入/签名请求。

### 7.4 请求级凭据快照

官方请求对象支持 ClientToken；共享官方 Client 不调用 `Auth().Login()` 或按业务请求 SetToken/SetNamespace。由内部请求执行器创建独立 Request，注入本次 Token 快照和固定 Namespace；配置对象启动后不可变。[S02][S03]

## 8. 请求执行器与重试

统一执行顺序：入口校验 -> 建立总预算 Context -> 等待并发槽 -> 取凭据快照 -> 创建独立请求 -> 调用官方 API Client -> 有界读取与关闭响应 -> 操作专用解码 -> 输出脱敏观察事件。

所有服务门面都走同一执行器，不能 PKI 使用 RawRequest、KV 使用另一个自带隐式重试的执行路径。模块可以利用官方类型，但不把官方响应或错误直接公开给业务。

### 8.1 operation registry

| 类型 | 操作 | 默认尝试上限 |
|---|---|---:|
| SAFE_READ | KV read/version/metadata/list；PKI cert/chain；Transit 公钥/元数据 | 3 |
| SINGLE_ATTEMPT_MUTATION | KV create/CAS/delete/undelete；PKI issue/sign/revoke | 1 |
| SINGLE_ATTEMPT_CRYPTO | Transit sign/encrypt/rewrap/HMAC | 1 |
| SINGLE_ATTEMPT_VERIFY | Transit verify/decrypt/HMACVerify | 1，V1 保守统一处理 |
| AUTH_ACTION | AppRole login/renew | 每个动作一次；生命周期另行调度 |
| HEALTH_PROBE | 集群健康 | 单次；健康状态不通过通用重试器转换 |

SAFE_READ 只对受控的连接错误、429、500/502/503/504 在预算内重试；429 要结合操作判断，健康接口的 429 是 standby 状态，不是普通限流错误。遵守受限 Retry-After，超过剩余预算直接结束。400/401/403/404、TLS 验证失败、解析不符合协议均不重试。

官方客户端配置 `MaxRetries=0`，重定向关闭；不能只关闭 SDK 外层重试。[S02][S03] net/http 还会按幂等方法或 Idempotency-Key 进行部分网络重试，所以 SDK 不给单次写操作添加 `Idempotency-Key` / `X-Idempotency-Key`。[S09] SDK 控制“不主动重放”；不宣称跨网络 exactly-once。Go Transport 可对安全读取或明确未发送的网络事件进行自己的处理，wire 级尝试数与 SDK Attempt 必须区分。

### 8.2 HTTP 返回与响应体

允许无返回数据的操作接受 200 或 204；需要关键数据的操作遇到 204 是协议错误，不能当成完整成功。错误体也有读取上限。官方 RawRequest 的错误解析可能先读取错误体，因此响应上限要加在 Transport 返回的 Body wrapper 层，而不是等到自己的 JSON decode 才检查。[S08]

4xx JSON、非 JSON 网关 HTML、空体、截断 JSON、重复 JSON 键、超大响应都要有契约测试。未知响应字段可忽略以便兼容；必要字段缺失和关键类型错误必须失败。

### 8.3 HA 与读后写

V1 默认要求配置指向可处理写入的 active endpoint，或具备服务器端请求转发的受控入口。不自动跟随任意 307/308；返回明确的重定向被禁止错误，由部署修复访问入口。

准确版本读取不等于任意副本的强一致性。写后验证应走同一受控读写入口；副本不可见只会让业务保持待核验，不能触发换版本、重新发证或回退根 Namespace。未来接入复制一致性头时必须作为显式能力增加，不依靠某个“默认强一致”开关宣称跨部署保证。

## 9. 错误契约

公开 baoerr.Error 至少包含：Code、Operation、HTTPStatus、RequestID（存在才填）、Attempts、Effect、脱敏 Message。Effect 独立于 Code：

| Effect | 含义 |
|---|---|
| NONE | 确知未产生本次业务副作用，如本地参数拒绝 |
| UNKNOWN | 服务端是否已执行不能可靠确认 |
| CONFIRMED | 有明确成功回执，但后续本地处理出现问题；仅在证据支持时使用 |

错误类别包含 InvalidArgument、AuthenticationFailed、PermissionDenied、NotFoundOrHidden、VersionUnavailable、CASConflict、Canceled、DeadlineExceeded、Unavailable、InvalidResponse、ResponseTooLarge、RedirectBlocked、NotReady、Closed。

具体分类表：本地取消发生在发送前为 NONE；发送后的写超时/断连/不明确 5xx 为 UNKNOWN；发证成功响应缺失关键私钥或证书字段不得再包装成普通可重试错误。读取不存在准确版本返回 VersionUnavailable 或 NotFoundOrHidden，取决于服务器提供的证据。

404 不保证不存在；403 不保证只是权限问题。只有已确认的 KV CAS 错误形态映射 CASConflict，不能假定 CAS 总返回 HTTP 409，也不能把所有 400 当成冲突。[S08][S10]

Error()、fmt、JSON、日志和 Tracing 均不包含秘密正文、Token、私钥和原始 HTTP 错误体。为支持 errors.Is，只 unwrap 经过筛选的安全 cause（如 context.Canceled/DeadlineExceeded），不能直接把可能含响应正文的官方 ResponseError 链式透出。

## 10. KV v2 设计

### 10.1 API 语义

Create 对应 cas=0；CompareAndSwap 要求 expectedVersion>0；ReadVersion 要求 version>0；ReadLatest 是独立方法，且返回实际版本；DeleteVersions/UndeleteVersions 必须传非空准确版本列表，不提供“删除全部”的快捷入口。[S10]

ReadVersion 不以 nil secret 作为成功，不把 data=null 当作正常空对象。若服务返回删除/销毁元数据，返回明确的 VersionUnavailable；若无法判定则保留 NotFoundOrHidden，不自动进行额外高权限元数据查询。[S02]

List 只列直接子项，不递归、不自动逐项读取正文。官方 LIST 空结果可能是 404，SDK 默认不能把所有 404 转为空列表；返回 NotFoundOrHidden，调用项目在明确业务条件下决定是否展示为空。[S08]

### 10.2 JSON 与数字

使用 `kv.Document` 保存一份独立 JSON 对象字节。NewDocument/ParseDocument 检查对象根、合法 JSON、重复键与深度；字节大小在配置控制的请求发送/响应读取边界执行，避免出现无法调整的第二套大小限制。Decode 到 map 时使用 UseNumber，确保 9007199254740993 不被 float64 转换损坏。禁止隐式字符串化整数。支持结构体、JSON 数组字段、bool 与 null 字段，根 null 不合法。

Document 的日志输出为 [REDACTED]；普通 json.Marshal(Document) 返回“需要显式揭示”错误，不能悄悄把秘密变成 [REDACTED] 写进 OpenBao。内部 wire 编码和受控业务交付使用 RevealJSON() 的拷贝。

### 10.3 引用与保留

KV Ref 包含 ClusterAlias、Namespace、Mount、Path、Version。Ref 是指针而非权限凭证；调用前仍校验它属于绑定客户端的受信配置。不可从不可信 Ref 选择外部服务器。

版本号并非永久内容地址。管理员删除 metadata、重建挂载或重用路径后，version=1 可能指向全新内容。因此业务需在加密正文里保存 `schema_version`、`resource_generation` 和操作标识，读取后核对；控制运维永久删除权限，安排备份与保留策略。

KV max_versions 可能清理旧版本，custom_metadata 属于键级可变信息，不是每个版本不可变的历史事实。操作标识、内容格式和材料 generation 必须与秘密正文放在同次 KV 写入，而不是另写 metadata。[S10][S11]

### 10.4 写后超时

cas=0 写超时后，业务在原路径读取并比对正文中 operation_id/resource_generation 等。只有证明是本次操作的结果才认定成功；只看到路径存在不足以证明。无法读取或比对失败保持结果未知。CAS 冲突不自动读最新再覆盖。

## 11. PKI 设计

Issue 只调用基于角色的发证路径，返回证书、私钥、签发 CA、证书链、序列号与实际有效期；不隐式写 KV。SignCSR 返回证书材料，不返回/假造私钥。ReadCertificate 返回证书，不提供“按序列号读取终端私钥”方法，因为普通 PKI 不保存签发的终端私钥。[S12]

签发算法和位数由管理员配置的 PKI Role 约束。Issue 请求不虚构普通端点不支持的任意 key_type/key_bits 参数。私钥编码固定请求 PKCS#8 PEM，证书固定 PEM，避免混合 pem_bundle 让私钥进入证书字段。[S12]

### 11.1 验证层次

输入：Role 不包含路径穿越；TTL>0；CN/DNS/URI/IP SAN 分别校验；URI/IP 使用标准解析器；CSR 必须可解析且 CheckSignature 成功。

返回：解析叶证书和私钥；检查私钥公钥与叶证书匹配；检查返回序列号、实际 NotBefore/NotAfter；SignCSR 检查证书公钥匹配 CSR。不能简单用 time.Now()+请求TTL 代替真实证书有效期。

独立的 `pki.ValidateBundle` 执行调用方传入信任根、期望用途和标识的校验。仅收到一条能自签的响应链，不等于建立了可信根；信任根来自受信部署配置。自动 AIA 抓取和在线 CRL/OCSP 检查不属于该本地函数，也不应在调用中产生隐藏网络请求。

证书读取受角色 no_store、保留及清理策略影响；查询不到不等于从未签发。证书续用不能按 Token 续租方式理解，更新证书是重新签发与业务切换。[S13]

### 11.2 吊销

Revoke 是维护动作，应使用独立受限身份。SDK 发出吊销并返回服务器回执，不承诺 EMQX、TLS 客户端或网关立即拒绝该证书；CRL/OCSP 分发与连接重建由基础设施设计负责。业务记录要保留旧证书的序列号、有效期、替换关系与吊销结果。

## 12. Transit 设计

### 12.1 密钥用途分离

平台签名私钥留在 Transit 中，运行时只获得 sign/verify/keys read 权限，默认不可导出。MQTT 客户端私钥需要交付终端，是另外一种材料。不能把“查询公钥”和“导出私钥”混成 ReadKey。[S14][S15]

终端独立业务私钥若确实必须由 OpenBao 生成并交付，走第 19 节管理端扩展；不能悄悄把平台签名密钥设为 exportable。若终端自行生成 CSR 或业务私钥，相关密钥生成归终端/业务层，不改变通用 SDK 的保管边界。

### 12.2 签名契约

V1 支持明确的安全 profile：ECDSA-P256 + SHA-256 + ASN.1 DER；RSA-PSS + SHA-256，密钥至少 2048 位，盐长语义固定；Ed25519 使用原消息。禁止调用时自动降级算法。默认业务建议 profile 是 ECDSA-P256，不暗示所有调用方必须使用该算法。

Sign 接收 Message 原始字节，内部只 Base64 编码一次；SignDigest 是单独方法，仅允许支持预散列的 profile，SHA-256 摘要必须为 32 字节。Ed25519 V1 不接受 SignDigest。业务 JSON 规范化、消息领域分隔、重放保护、时间戳和 nonce 都在上层协议完成，SDK 不对任意对象自动序列化签名。

签名要求 key_version>0，不以 0 表示 latest。结果保留原始 `vault:vN:...` 包装、实际 KeyVersion 和签名格式。验证要检查包装版本与预期 KeyVersion 一致，错误版本不能悄悄使用最新公钥。官方 Transit 在未指定版本时使用最新版本，这是本 SDK 刻意收紧的契约。[S14]

ReadPublicKey(name, version) 是 SDK 组合方法：读取密钥元数据，从指定版本提取公钥并解析验证；不是假造 `GET /transit/keys/name/version`。ReadKeyMetadata 的 keys 值随算法类型不同，不能把对称密钥创建时间当公钥。[S14]

Verify 的 `valid=false,error=nil` 表示服务器成功判断签名无效；格式非法、调用失败或协议异常返回 error。离线本地验签作为工具函数可后续扩展，但不能把缓存公钥等同于持续有效的业务授权。

### 12.3 加密、重包裹与 HMAC

Encrypt 指定 key version，使用已存在的 AES-GCM 密钥，不授予 encrypt 路径上的自动创建能力；传入字节由 SDK 编码，明文不记录。Decrypt 使用密文内编码的版本与必要的派生 context，不强行添加不存在的解密 key_version 参数。Rewrap 指定目标版本，业务以 CAS 切换保存的密文。

V1 不接受自定义 nonce、不启用 convergent encryption、不生成 data key，不处理任意大文件；大对象信封加密是独立扩展。HMAC 明确指定版本和 SHA-256；它不能替代任何“公开验证签名”的要求。

Transit 是密码学操作服务，不替调用方持久化业务明文或密文；输出的签名/密文及其 key reference 由业务保存。[S15]

## 13. 敏感材料与可观测性

`sensitive.Bytes` 使用私有字段保存拷贝，String、GoString、Format、slog.LogValue 固定脱敏；普通 JSON 序列化返回显式错误；RevealCopy 只返回新拷贝，使用者对拷贝负责。Zero 方法仅尽力覆盖当前持有的切片，不承诺清除 Go 运行时、TLS、字符串和调用方拷贝中的所有历史内容。

SDK 默认不记录任何请求/响应 body。Token、SecretID、私钥、秘密 JSON、CSR 中的业务标识、完整路径及官方原始错误不进入常规日志/Tracing。SDK 自己的默认日志开销为零；Observer 只接收允许字段。

允许的指标标签：操作枚举、错误类别、HTTP 状态类别、静态集群别名、配置里的有限 mount 标签。禁止把 terminal_id、tenant_id、秘密路径、serial、request_id 放进指标标签。关联标识可进入受控日志而非高基数指标。

Observer 是非阻塞回调契约：调用方实现必须快速完成；SDK 不默认创建无限异步队列。Observer panic 被边界捕获，不能把已成功写入改判为失败。审计事件需要由业务单独可靠投递，普通 Observer 不替代审计/outbox。

## 14. 授权与路径边界

一组 Client 固定绑定 Address、Namespace、认证主体；同一主体令牌可更新，不允许切换为其他租户身份。业务 tenant_id 不能直接成为 Namespace 或 secret path；服务先完成业务授权，再从可信配置映射。

按路径段校验 mount、role、name 和 secret path；拒绝空段、`.`、`..`、反斜杠、控制字符、查询/片段分隔符、预编码路径分隔等；只规范化文档允许的尾分隔，不能使用 path.Clean 把恶意输入“修好”后继续请求。V1 命名采用 ASCII 字母数字、下划线、连字符和非结尾点号的受限集合；不是宣称覆盖 OpenBao 接受的所有 Unicode 路径。CN/SAN 不适用该资源路径字符集。

最小策略示例在 `xyouting-test` Namespace 内应用，不能再把 Namespace 重复拼在该 Namespace 的 policy path 中：

```hcl
# 签发/保管服务：只允许一个固定 PKI role 与一段凭据路径。
path "pki-device/issue/terminal-mqtt" {
  capabilities = ["update"]
}
path "kv-credentials/data/provisioned/*" {
  capabilities = ["create", "read"]
}
```

下面是另一份独立策略，只授予控制服务；不要把两个示例合并后同时授予一个普通服务身份。

```hcl
# 控制服务只使用签名与公钥，不获得上述凭据存储权限。
path "transit/sign/platform-control" {
  capabilities = ["update"]
}
path "transit/keys/platform-control" {
  capabilities = ["read"]
}
```

这里的角色名和路径均为示例，不是现网事实。需要 CAS 更新的服务另授 update；需要列表另授 metadata/list；需要续期另授对应 token 自续期权限。不能为了 readiness 一次性授予 sys/* 或所有 metadata/read。KV 的 data/metadata/delete/undelete 权限路径不同，必须真实集成验证。[S11]

## 15. 健康与就绪

State 为本地状态，不联网。ClusterHealth 使用独立、无 Token、无 Namespace 的只读客户端调用根级 sys/health；这是明确的集群诊断，不是业务失败后的根空间回退。返回 initialized、sealed、standby 和原始 HTTPStatus。

OpenBao 健康接口有 200 active、429 standby、501 未初始化、503 sealed 等语义；不得一概变成传输失败。[S16] 名称空间业务就绪另外使用其受限凭据读取一份已知准确版本的非秘密 sentinel，或执行真正需要的只读操作。根级健康不证明 Namespace、role、KV 或 Transit 权限可用。[S04]

默认不启动健康轮询 goroutine，不读取 sys/mounts 进行全局探测。是否影响 HTTP readiness 由宿主服务按其业务依赖决定。

## 16. 在游艇项目中的接入与失败恢复

本节是**业务接入参考**，不把字段和状态放入 SDK。保留既定顺序：先创建游艇实例和终端标识，再准备各终端凭据；全部保存并核验后才能生成注册码。失败不能重复创建游艇或终端。

```text
业务创建游艇实例及终端清单
 -> 为每终端建立凭据准备任务（operation_id、generation）
 -> PKI.Issue 得到 MQTT 证书/私钥/链
 -> pki.ValidateBundle 校验用途、信任根与匹配性
 -> KV.Create 写入同一份完整材料文档
 -> ReadVersion 按返回准确版本核验
 -> 保存 Ref、证书序列号/指纹/到期时间和任务状态
 -> 独立业务密钥也保存并核验完成
 -> 所有终端 READY 后生成注册码
 -> 注册认证与认领校验通过后读取准确版本并受控交付
```

秘密正文建议业务封装：schema_version、operation_id、resource_generation、purpose、certificate_pem、private_key_pem、ca_chain_pem、serial_number、not_before、not_after。平台 Transit 私钥不出现在此交付包；不同用途的终端私钥不复用。

每一次凭据 generation 使用新的不可复用路径，例如 `provisioned/{opaque-terminal-id}/{generation}/mqtt`；配置/数据库保留 Ref，绝不将随机性不足的业务属性当作访问控制。私钥不写入 MySQL、消息队列、webhook、普通 audit/outbox payload、URL 或 MQTT。通知只携带受控的公开标识/证书指纹或供授权服务解析的引用。

| 失败窗口 | 业务恢复要求 |
|---|---|
| 发证前失败 | 任务保留待处理，可重新进入明确未执行步骤 |
| 发证响应丢失 | UNKNOWN；可能已有证书，无法取回私钥；禁止普通自动重试 |
| 发证成功、KV 保存失败且进程仍持有完整材料 | 只受控重试保存原材料，不能再发一套 |
| KV 写入超时 | 读取原路径比对 operation_id/generation，不能仅凭“存在”判成功 |
| KV 成功、MySQL 更新失败 | 用业务任务与确定路径恢复引用和实际版本 |
| 进程在签发与保存间崩溃 | 无法保证原私钥恢复；进入人工/受控补发和旧证书处置流程 |
| 准确版本暂不可见 | 保持待核验；不回退 latest、不生成注册码 |
| 已保存版本被删除/内容 generation 不符 | 阻止交付并告警，不能静默重建 |
| 发码前发现证书已经临近到期 | 由业务启动新凭据 generation，再次核验 |

PKI、KV、MySQL 不存在本 SDK 提供的原子事务。业务通过短事务、任务状态、幂等标识和补偿完成协同，不跨外部请求持有长数据库锁。

## 17. saas-go 与其他项目接入

SDK 使用独立可访问仓库地址和语义化 tag。开发时可用本地 go.work 临时组合；发布验收必须 `GOWORK=off`，确保每个消费者确实依赖发布版本，而不是依靠工作区替换隐藏缺包问题。

saas-go 的服务 bootstrap 创建 Client；业务通过自己的窄接口依赖，例如 CertificateIssuer、SecretVersionReader、MessageSigner，而不是把整个 SDK Client 传进所有 service。项目错误码由 adapter 映射，SDK 不引入 saas-go/shared/errno。[P01]

迁移按一个只读消费者 -> 一个低风险写消费者 -> 其他服务逐步切换。测试环境比对引用与协议，不进行双写发证/双写轮换。“新旧双跑”只限明确只读、无敏感泄漏的路径。回滚 SDK 版本不等于回滚已轮换的密钥或已发放的证书。

## 18. 测试、发布与交付标准

单元测试负责配置/路径/编码/错误/状态机；httptest TLS 契约负责真实 HTTP 路径、权限头、次数、超时和异常响应；临时真实 OpenBao 负责认证、ACL、CAS、PKI、Transit 和 Namespace 隔离。mock 测试不能证明真实服务器兼容。

关键门槛：core/authn/kv/pki/transit/baoerr 每个目标包行覆盖率目标至少 85%，但覆盖率不能替代逐项失败场景；race 检查必须通过；examples 必须编译；不设虚构吞吐 SLA，基准测试记录环境、并发、证书算法、样本数和分位耗时。

正式集成 job 必须显式启用；环境缺失即 job 失败，不能所有测试 skip 后显示绿色。普通单元 job 可以不执行 integration。Namespace、TLS 和跨项目真实接入没有完成时，不能给全域 PASS。

发布使用语义化版本与变更日志；v0 为试用期，v1 明确兼容承诺，破坏性变更用新主版本及相应模块路径。[S17] SDK 依赖、漏洞扫描工具、服务镜像、测试配置均固定版本。供应链扫描结果人工确认可达性与影响，不把“扫描命令执行过”当作“没有漏洞”。

## 19. 管理端扩展方案（不进入 V1 运行时）

需要跨项目复用创建/轮换/导出能力时，单独建立 `management` 包或独立模块，使用独立构造器和凭据；普通 Client 不暴露 Admin() 逃生入口。它复用经过审计的 transport/auth 基础，但不共享运行时业务令牌。

第一组扩展只覆盖 Transit CreateKey、ReadKeyConfig、RotateKey；禁止全能 sys 写接口。CreateKey 针对已经存在的名称要检查完整期望配置，不宣称服务端支持原子的 create-only。RotateKey 未收到响应为 UNKNOWN，不能自动重放；读到 latest_version 增加不一定证明是本次请求造成，需要唯一操作者/运维任务证据。

第二组是需交付终端的独立业务私钥：仅在业务已明确要求时，使用专用 Transit mount 和 key purpose，创建 exportable=true 的专用密钥，再显式 ExportPrivateKeyVersion，保存到受限 KV 并返回受控交付引用。平台签名 key 禁止使用此配置。exportable 一旦开启不能关闭；删除管理端导出方法或删除 KV 拷贝也不能让已导出的秘密“收回”。[S14]

导出接口必须传准确版本，回执包含 key purpose 和 generation；本地私钥校验后仅明确保存/交付。密钥创建、导出、KV 保存同样不是原子事务。SDK 不以 PKI CA key API 冒充通用可导出终端业务密钥生成器。

数据库动态凭据、SSH、Kubernetes/JWT、response wrapping、批量 Transit、信封加密及 CA 管理以后分别定义小规格与测试，不让“完整方案”变成未经验证的全 API 镜像。
