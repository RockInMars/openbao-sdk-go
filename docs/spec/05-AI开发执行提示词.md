# Claude Code / Codex 开发执行提示词

下面内容用于把本方案交给已经获得代码仓库访问权的开发代理。它是后续执行指令模板；本次生成该文件不代表已经授权或执行任何生产操作。

```text
你是本项目的 Go 基础设施 SDK 实现负责人。请依据当前目录提供的方案，实际实现可供其他 Go 项目依赖的 OpenBao SDK，而不是只输出建议、伪代码或接口占位。

首先读取：
01-总体设计.md
02-接口契约.md
03-实现任务计划.md
04-验收矩阵.md
06-资料依据.md
task-status.json

目标与边界：
1. 独立 Go Module，仓库建议名 openbao-sdk-go。官方 github.com/openbao/openbao/api/v2 是底层，不使用 OpenBao 插件开发 SDK 代替业务客户端。
2. 核心范围为 Core/Auth/KV v2/PKI/Transit/Diagnostics/Observability、示例、测试和发布规范。具体公开签名以 02 为准。
3. 不引入 Gin、Fiber、Gorm、Redis、EMQX、MySQL 或 saas-go 领域依赖。游艇创建、终端注册、业务密钥用途、业务状态机、KV+MySQL恢复只在示例或调用项目中编排。
4. 管理端 MG-001/MG-002 不属于运行时 V1 默认执行范围；不得为补齐运行时功能而偷偷增加管理权限或导出私钥。

执行方式：
先检查真实仓库 AGENTS.md/CLAUDE.md/go.mod/git status，保留用户未提交改动；不要覆盖或回滚无关改动。读取计划后核对接口定义、包依赖和现有实现，只补缺口，不重复创建已完成能力。
从最早一个无阻塞的 OB 任务开始，逐任务 TDD：补失败测试、运行确认失败、实现、运行目标及回归测试、记录证据、审查diff。不要只创建声明就标为完成，不要用panic、TODO、固定成功返回或mock实现冒充生产实现。
同一文件上的并行任务由一个集成人协调；公开契约未稳定前不并行修改client/config/go.mod。没有子代理就串行执行，不因工具缺失停下。

首先完成 OB-001：
核对候选 api/v2@v2.7.0 的真实 go.mod 和目标部署兼容性；固定精确客户端依赖、Go工具链、module path、临时服务镜像tag/digest。不能把候选版本称为最新或已兼容现网。涉及需要用户实际仓库地址的发布步骤可记录外部依赖，但先完成不依赖远端发布的代码和测试。

必须遵守的安全与语义：
- SDK配置显式传入，不自动读取BAO/VAULT/代理环境；官方NewConfig，MaxRetries=0；两层自动重定向禁用。
- HTTPS验证CA和服务名，不关闭验证。测试HTTP例外仅用于专用loopback测试构造器，不进入正常运行接口。
- Client固定绑定集群、Namespace和身份；请求持有不可变Token快照；禁止并发SetToken/SetNamespace切换业务身份。
- Namespace零值无效；xyouting-test的部署映射不能猜测。任何错误不能回退root、latest、其他认证方式或更宽权限。
- SAFE_READ最多3次SDK尝试，总预算10秒；发证/CSR签名30秒；写、crypto、认证动作默认单次。不添加Idempotency-Key/X-Idempotency-Key来假造OpenBao幂等。
- PKI.Issue只签发，不自动保存私钥。普通PKI不能按证书序列号取回终端私钥。完整材料的KV保存由业务显式调用。
- KV.Create采用cas=0；CAS更新必须传预期版本；ReadVersion/ReadRef必须准确版本；删除与恢复必须明确版本列表；不提供永久销毁捷径。
- KV大整数无损，重复键/超深/异常响应拒绝。custom_metadata不能当版本历史事实。
- Sign/SignDigest分开，版本和算法明确；私钥默认不导出；public key读取不能把对称密钥时间戳当成公钥。
- timeout/connection reset/模糊5xx不能把写结果归为“肯定失败”。保留Effect=unknown，并支持调用方检测Context错误。
- Token、SecretID、私钥、秘密JSON和原始错误响应不进日志、Tracing、错误、截图、测试报告、git diff说明或工单正文。
- Close不撤销外部Token、不删除秘密、不吊销证书；不得影响调用方其他共享资源。

测试与真实性：
以04的72项验收逐项建立证据，明确区分单元、HTTP契约、临时真实OpenBao、消费者集成。
真实集成仅在临时local/dev/test资源上执行，初始化用临时管理员，业务断言用最小权限身份。
专用集成CI缺环境时必须失败，不能全skip后给出PASS。
两个独立go.mod消费者使用GOWORK=off，通过预发布tag或CI临时module proxy验证，不用本地replace假装发布依赖已经可用。
记录实际命令、退出码和脱敏输出；没有执行过的测试标NOT_RUN。覆盖率目标逐包检查，不以总平均值掩盖关键包缺测试。

环境与阻塞：
不读取或输出真实生产凭据，不操作production/prod/staging、不修改生产OpenBao/CA/ACL/数据库。
遇到生产配置、外部控制权、真实凭据、缺少实际业务仓库等阻塞，只阻塞相应任务并写明原因，继续下一项独立可完成任务。不得通过关闭安全校验、扩大权限、伪造回执或修改验收标准绕开阻塞。
不要每完成一个小任务就停下来等待我确认；在当前执行会话内继续所有已授权且无阻塞的任务。不要承诺会话结束后后台继续工作。

每个阶段结束输出：
本阶段完成的任务ID和修改文件；实际测试命令与结果；对应验收项；未完成/阻塞及原因；安全审查发现；下一可执行任务。
维护task-status.json与脱敏evidence目录。最终报告分别给出“SDK实现状态”和“业务项目接入状态”，不得把设计完成、接口存在、单测通过、真实环境验证这四者混为一谈。
```

